# PRD: бот-фільтр каналу @chyste_nebo

Документ фіксує продукт до реалізації.

## 1. Проблема

Канал [@chyste_nebo](https://t.me/chyste_nebo) («Чисте небо Київська область та Київ») публікує хвилинні оновлення про повітряні загрози: напрямок, орієнтовний час, статус («зняли», «відбій»). Потік щільний і стосується всієї області. Потрібно отримувати лише пости, релевантні своїм населеним пунктам / типам загроз, у окремій групі (родина, сусіди), без ручного скролу каналу.

## 2. Мета і успіх

**Мета:** у групі з’являється сповіщення протягом кількох секунд після поста в @chyste_nebo, якщо в тексті/підписі є хоча б одне ключове слово зі списку власника.

**Успіх MVP:**

- пропуск жодного релевантного нового поста при працюючому процесі (не рахуючи даунтайм хоста);
- нуль алертів, якщо список слів порожній;
- власник додає/видаляє слова в приваті з ботом без рестарту;
- затримка від публікації в каналі до повідомлення в групі — зазвичай < 5 с.

## 3. Користувачі і ролі

- **Власник (ви):** єдиний, хто керує ключовими словами в приватному чаті з ботом; прив’язує групу доставки.
- **Учасники групи:** лише читають алерти. Команди керування в групі ігноруються.

Авторизація власника: `OWNER_ID` / `TELEGRAM_OWNER_ID` (числовий user id). Інші користувачі в DM отримують коротку відмову.

## 4. Рішення, уже зафіксовані

- Доставка: **окрема група / чат**, не особисті повідомлення.
- Керування словами: **лише власник, команди в приваті**.
- Пошук: **підрядок без урахування регістру**, з простою основою слова (остання літера відмінка). Приклад: ключ `Буча` спрацьовує на `буча`, `Бучі`, `На Бучу`. Також спрацює на `Бучач`.
- Стек: **Node.js** (grammY + GramJS + SQLite).

## 5. Обмеження Telegram (архітектура)

Bot API **не вміє** читати довільний публічний канал, якщо бота туди не додали як адміністратора. @chyste_nebo нам не підконтрольний.

Тому два клієнти в одному процесі:

- **MTProto (GramJS, user session)** підписаний на канал, слухає події.
- **Bot API (grammY)** приймає команди власника і шле алерти в групу.

## 6. Функціональні вимоги

### 6.1 Моніторинг каналу

- Джерело: лише `@chyste_nebo` (username у конфігу).
- Вхід: нові пости і редаговані пости.
- Текст для матчингу: текст або підпис. Порожній текст без підпису — ігнор. OCR — ні.
- Історія каналу при старті не розгрібається.

### 6.2 Матчинг

- Нормалізація: Unicode case-fold, зайві пробіли всередині ключа не важливі.
- Збіг, якщо хоча б один ключ є підрядком тексту.
- Кілька ключів у одному пості → один алерт з переліком збігів.
- Порожній список ключів → жодних алертів.
- Дедуп: пара `(channel_id, message_id)`. Редагування: повторний алерт лише якщо з’явився новий ключ.

### 6.3 Доставка в групу

- які ключі спрацювали;
- повний текст поста (або підпис), обрізати лише якщо > ліміту Telegram;
- посилання `https://t.me/chyste_nebo/<message_id>`;
- час поста (Europe/Kyiv);
- без web preview;
- помилка доставки в групу: лог + одне DM власнику, cooldown 15 хв.

### 6.4 Команди власника (тільки DM)

- `/start` — допомога
- `/add <слово>` — додати ключ
- `/remove <слово>` — видалити ключ
- `/list` — список
- `/pause` / `/resume` — пауза алертів
- `/status` — стан
- `/setgroup` — у групі прив’язує destination; у DM — інструкція

Правила слів: 2–64 символи, без нового рядка, ліміт 50, порівняння case-insensitive.

Не власник: «Цей бот особистий.»

## 7. Не входить у MVP

Кілька каналів/груп/власників, веб-UI, морфологія, regex, AI, бекфіл історії, читання чату обговорення.

## 8. Нефункціональні вимоги

Event-driven (не cron), збереження ключів і групи після рестарту, логи match/skip/send, секрети лише в env, інтерфейс українською.

## 9. Дані

SQLite: `keywords`, `settings`, `sent_alerts`.

## 10. Стек

- Node.js 22+
- TypeScript
- **grammY** — команди і відправка в групу
- **teleproto** (MTProto, форк GramJS) — слухач каналу
- SQLite (`node:sqlite`)
- `.env`: `BOT_TOKEN`, `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `OWNER_ID`, `CHANNEL=@chyste_nebo`

## 11. Ризики

Сесія особистого акаунта, false positive через підрядки, даунтайм без догону історії.

## 12. Критерії приймання MVP

1. Пост із ключем → одне повідомлення в групі з текстом, ключами і лінком.
2. Пост без ключів → тиша.
3. `/add`, `/remove`, `/list` змінюють поведінку одразу.
4. Той самий `message_id` не дублюється; edit з новим ключем — так.
5. Чужий user у DM не керує списком.
6. `/setgroup` від власника в групі перемикає destination.
7. `/pause` / `/resume` працюють.
8. Рестарт зберігає ключі і `dest_chat_id`.
